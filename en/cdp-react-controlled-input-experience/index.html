Filling React Controlled Inputs with CDP: Bypassing the Virtual DOM

Created2026-06-09|Updated2026-06-09|CDP PracticeExperience Sharing
|Post Views:

Summary in one sentence: React controlled components hijack the input’s value property — el.value = x won’t update React state. The fix: obtain the native value setter via Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set, set the value bypassing React, then dispatch input/change events to trigger React’s state sync.

The Problem

On a novel platform’s author dashboard, I needed to auto-fill chapter titles. The most intuitive approach:

The input field displayed the text visually, but when clicking “Save,” React received an empty value. The DOM showed the value, but React’s internal state didn’t reflect it.

How React Controlled Components Work

React controlled components work like this:

React overrides the value property’s getter and setter on each input instance:

  1. Direct el.value = x → calls React’s overridden setter → React ignores it
  2. User input → triggers input event → React captures event → calls setState → updates value

The key insight: React listens for events, not property changes. Simply changing the property doesn’t fire events, so React doesn’t know the value changed.

Failed Attempts

Why does dispatching an input event still fail? Because React overrides the value getter — el.value returns React’s state value, not the actual DOM property. When the event fires, React reads the getter and gets the old value.

The Correct Approach: Native Setter Bypass

The solution: get the native value setter that existed before React overrode it, use it to set the value, then dispatch events to trigger React sync.

Step-by-step Explanation

  1. Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set

    • Gets the setter from the prototype level (before React overrides it per-instance)
    • React overrides the setter on each element instance, not on the prototype

  2. nativeSetter.call(el, value)

    • Applies the native setter to the specific element
    • Bypasses React’s instance-level getter/setter, directly modifying the real DOM property

  3. el.dispatchEvent(new Event('input', {bubbles: true}))

    • React listens for input events to sync state
    • After the event fires, React’s onChange handler runs setState with the correct value

Summary

  1. React controlled components ignore el.value = x because React overrides the value property
  2. The fix: obtain the native setter from HTMLInputElement.prototype, bypass React’s interception
  3. Must dispatch events: fire input + change after setting to trigger React state sync
  4. Textarea works the same way using HTMLTextAreaElement.prototype.value
  5. Focus first: some libraries require the input to be focused before accepting input

Summary: Understanding React’s controlled component mechanism — where value getters/setters are overridden — is the key to solving this. The native setter bypass + event notification pattern works not only for React but also for Vue, Angular, and other frameworks using similar mechanisms.
