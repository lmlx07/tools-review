API Submission Script Development: From Sitemap to Search Engine Indexing

Created2026-06-09|Updated2026-06-09|SEO PracticeExperience Sharing
|Post Views:

Summary in one sentence: A 100-line Python script that periodically extracts URLs from sitemap.xml, compares them against submitted records, and submits new ones in batches to the search engine API. The core design is “submit only new URLs, don’t waste daily quota, resume from checkpoint.”

Why This Script Is Needed

Static sites (GitHub Pages, Vercel, etc.) have no backend server, so they can’t automatically notify search engines when new articles are published. After each new article, you’d need to manually submit the new URL to search engines — tedious and easy to forget.

Pain points of manual submission:

  • Open the webmaster platform → paste URLs → submit
  • Hard to remember which URLs were already submitted
  • Limited daily quota means wasteful submissions hurt

Running and Maintenance

Script features:

  • Idempotent: Re-running won’t re-submit already-submitted URLs
  • Checkpoint resume: Run daily, each time only submitting new URLs
  • Quota-aware: Batch size never exceeds remaining quota, preventing batch rejection
  • Auto-skip: Already-submitted records are automatically skipped

Issues Encountered and Solutions

Issue 1: Windows Encoding

Cause: Windows console defaults to GBK encoding. print() with special characters throws an error.

Solution: Redirect stdout:

Also, avoid emoji in print statements — Windows emoji support is unreliable.

Issue 2: Batch Exceeding Remaining Quota

API returns {"error":400, "message":"over quota"}.

Cause: Submitting 10 URLs when only 7 quota remain — the entire batch is rejected.

Solution: Set batch size to 5, and check remain after each submission.

Issue 3: Quota Doesn’t Reset

For unlicensed GitHub Pages sites, the API quota may be a one-time total limit rather than a daily reset.

Solution: Switch to manual submission once the quota runs out.

Summary

  1. Design principles: Idempotent (no duplicates) + Incremental (new only) + Quota-aware (never exceed limits)
  2. Key technologies: Sitemap parsing + JSON records + Batch POST + Error handling
  3. Maintenance cost: Nearly zero — run the script after each deploy, it auto-skips already-submitted URLs
  4. Good extensibility: Can expand from a single search engine to multiple, or integrate into CI/CD pipelines

Summary: The value of this 100-line script isn’t the code volume — it’s the design philosophy: idempotency, incremental processing, and quota awareness. These same principles apply to automation in any API rate-limited scenario.
