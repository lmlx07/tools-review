Complete SEO Guide for Unlicensed GitHub Pages Sites

Created2026-06-09|Updated2026-09-11|SEO PracticeExperience Sharing

Summary in one sentence: GitHub Pages .com domains cannot get ICP filing, making sitemap submission and search analytics unavailable. But by combining file verification with API submission, you can still get indexed. The key is choosing the right verification method and submission channel.

The ICP Filing Dilemma with GitHub Pages

GitHub Pages assigns a xxx.github.io domain. If you bind your own .com domain (e.g., example.com), you’ll run into these issues:

Feature Needs ICP Filing? GitHub Pages Compatible?
Domain binding ✅ Required ❌ .com domains can’t file
Sitemap submission ✅ Required ❌ Unavailable
Search analytics ✅ Required ❌ Unavailable
API submission ❌ Not required ✅ Available
Manual submission ❌ Not required ✅ Available
File verification ❌ Not required ✅ Available

The core conflict: GitHub Pages is a foreign service and cannot obtain ICP filing from China’s MIIT. Certain advanced features on some search platforms (sitemap submission, search analytics) require a filed domain.

The good news — basic indexing features (API submission + manual submission) do not require filing.

Webmaster Platform Three-Step Setup

Step 1: Add Site

On the webmaster platform, select “Add Site” and enter your domain (e.g., https://lmlx07.github.io/tools-review).

Step 2: Verify Site Ownership

Three verification methods:

  1. File verification (recommended) → Download a verification file → Place it at your site root
  2. HTML tag verification → Add a meta tag to your homepage <head>
  3. CNAME verification → Add a TXT record to your DNS settings

For GitHub Pages, file verification is recommended.

Step 3: Submit for Indexing

Once verified, you can submit URLs (see sections below).

Verification Method: File vs HTML Tag

File Verification (Recommended)

The webmaster platform generates a verification file, e.g., baidu_verify_codeva-xxx.html.

Steps:

  1. Download the verification file
  2. Place it in your Hexo source/ directory
  3. Configure skip_render (critical!)
  4. Run hexo g -d to deploy

HTML Tag Verification

While usable, it’s trickier with Hexo — you need to modify theme templates, and theme updates can overwrite your changes.

Why File Verification Wins

Aspect File Verification HTML Tag Verification
Complexity Simple (drop a file) Need to modify template
Persistence Permanent (don’t delete the file) Theme updates may lose it
Impact scope Single file Affects full-site template
Hexo interference ⚠️ Needs skip_render No impact

Hexo skip_render Configuration

This is the most commonly overlooked step.

Without skip_render, Hexo’s rendering engine treats the verification file as a regular page — adding layout, header/footer HTML structure. But the search engine expects the verification file to be plain/raw HTML. Hexo’s rendered version will cause verification to fail.

Three Submission Methods Compared

Method Needs Filing? Automation Quota Recommendation
Sitemap submission ✅ Yes Fully automatic ⭐ Unlimited ❌ Unavailable
API submission ❌ No Script-based ~10/day ⭐⭐⭐ Best choice
Manual submission ❌ No Manual paste Unclear ⭐⭐ Backup

API Submission (Recommended)

Send POST requests from your local machine to the webmaster platform’s API endpoint — no server-side support needed.

How it works:

See the dedicated article “API Submission Script Development Practice” for details.

Manual Submission (Backup)

When API quota runs out, paste URLs manually on the webmaster platform’s “Manual Submission” page.

Quota Limitations

For unlicensed GitHub Pages sites, API submission has these limits:

Limit Description
Daily quota ~10 API submission allows roughly 10 URLs per day
Per-batch ≤ remaining quota Submitting 10 when only 7 remain will reject the entire batch
Quota may be one-time Unlicensed GitHub Pages sites may only get a total quota, not daily reset
No sitemap submission Unavailable due to filing requirements

Suggestion: Switch to manual submission once the API quota is exhausted.

Tips for Faster Indexing

  1. Keep publishing: More articles and frequent updates increase your site’s search engine weight
  2. External links: Share your articles on platforms like Zhihu, Dev.to, Medium with links back to your site
  3. Manual supplementation: After API quota runs out, add manual submissions
  4. Patience: New sites typically take 1~4 weeks to get indexed

Summary

Step Key Point
Verification method Choose file verification, place in source/ directory
Critical config Must configure skip_render or the verification file gets corrupted by Hexo
Submission method API submission as primary, manual submission as backup
Expectation management New sites take 1~4 weeks for indexing; unlicensed sites face more restrictions

Summary: Unlicensed GitHub Pages sites can’t use sitemap submission or search analytics, but the “file verification + API submission” combination is fully capable of getting you basic indexing. The key is setting up skip_render correctly, choosing the right submission method, and maintaining reasonable expectations about indexing time.
